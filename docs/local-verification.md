# Local Verification

This repository can verify the web app, backend API, parser, queue state machine, and Docker packaging locally.

Run the full local gate after code changes:

```bash
bun install
bun run typecheck
bun run lint
bun test
bun run build
bun run docker:build
```

With the API already running on `http://127.0.0.1:8787`, run the local MT5 contract smoke:

```bash
bun run mt5:smoke
```

That smoke registers a unique demo account, sends an MT5 heartbeat, parses and approves an
`OPEN_TRADE`, leases the line-oriented `/api/mt5/poll-line` payload, reports an executed retcode
through `/api/mt5/report`, then repeats the same lease/report loop for a lifecycle command matched
to the logical trade. It proves the backend contract used by the EA, but it does not compile the
`.mq5` file or place a trade inside a real MetaTrader terminal.

The MT5 Expert Advisor source is in `mt5/TelegramTC_EA.mq5`. Local Codex runs can statically inspect the file and verify the backend payloads it consumes, but compiling and executing the EA requires MetaTrader 5 with the backend URL added under allowed WebRequest URLs.

Real Telegram verification requires a Telegram API ID/hash and a phone number. Run the API with
`TELEGRAM_ADAPTER=gramjs`, complete the frontend code/2FA flow, load dialogs, select a provider,
then open Parser Lab against recent messages. Session strings are stored only in ignored local
files under `data/telegram-sessions/`.

MT5 demo-terminal verification should cover:

- EA account registration and heartbeat.
- `/api/mt5/poll-line` leasing a pending command.
- Market and pending order execution through `MqlTradeRequest`.
- Retcode-aware reporting through `/api/mt5/report`.
- At least one lifecycle command, such as `MOVE_SL_TO_BE` or `CANCEL_PENDING`.
- Split-order mode creating one child request per TP leg.
- Virtual-TP mode closing planned partial volumes at TP1-TP4 thresholds.
- Trailing-stop commands converting pips/points through the broker symbol point size.
- Hedging vs netting account behavior for partial closes.

See `docs/mt5-demo-terminal-verification.md` for the full manual demo-terminal runbook.

The EA intentionally consumes a line-oriented poll payload to avoid complex JSON parsing in MQL5. Reports back to the API are JSON because the payload is small and generated by the EA.
